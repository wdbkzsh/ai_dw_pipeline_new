# SQL生成指令（sql-generate.md）

## 一、任务目标

根据项目模型设计、字段映射、指标实现分析，生成可执行的数据仓库SQL。

输入资料：

-   model_design.md
-   model_design.yaml
-   mapping.yaml
-   metric_implementation.yaml
-   data_analysis.md
-   sql_rule.md
-   sql_style_rule.md

输出：

生成完整SQL脚本，包括：

1.  FACT建表SQL
2.  FACT加载SQL
3.  TMP节点SQL（如需要）
4.  ADS建表SQL
5.  ADS加载SQL

SQL必须满足 sql_rule.md 规范。

------------------------------------------------------------------------

# 二、SQL生成总体流程

严格按照以下顺序：

    业务分析
     ↓
    确认FACT粒度
     ↓
    生成FACT DDL
     ↓
    生成FACT INSERT
     ↓
    设计TMP节点
     ↓
    生成TMP SQL
     ↓
    生成ADS DDL
     ↓
    生成ADS INSERT
     ↓
    生成验数SQL

禁止直接从源表生成ADS。

------------------------------------------------------------------------

# 三、FACT生成规则

## 1. FACT定位

FACT用于沉淀业务事件。

生成前必须读取：

-   business_process
-   fact_grain
-   source_tables
-   mapping

------------------------------------------------------------------------

## 2. FACT字段要求

FACT字段分为：

### 必备字段

必须包含：

-   ETL_BIZ_DT
-   ETL_PROC_TM

### 事件字段

例如：

-   BILL_DK
-   BILL_BK
-   EVENT_DT

### 业务关联字段

例如：

-   REARER_ID
-   REARER_POP_ID
-   ORG_ID

### 状态字段

例如：

-   STATUS_CD
-   STATUS_NM

### 分类字段

例如：

-   ALERT_METRIC_CD
-   RISK_CATEGORY_CD

### 度量字段

例如：

-   DURATION_DAY

原则：

不要只生成当前ADS需要字段。

保留具有业务分析价值的字段。

------------------------------------------------------------------------

## 3. FACT粒度检查

生成SQL前必须输出：

    FACT名称：
    业务过程：
    粒度：
    主键：
    来源表：

如果JOIN导致粒度变化，必须重新设计。

------------------------------------------------------------------------

# 四、TMP节点设计规则

## 1. 什么时候生成TMP

满足以下任意条件：

-   一个FACT多次扫描
-   多个指标使用相同计算逻辑
-   存在复杂JOIN
-   存在多层聚合
-   ADS SQL过长

必须拆TMP。

------------------------------------------------------------------------

## 2. TMP命名

格式：

    TMP_业务主题_用途

例如：

    TMP_ANOMALY_STATUS_BASE
    TMP_CAUSE_ANALYSIS_METRIC

------------------------------------------------------------------------

## 3. TMP必须说明

每个TMP前添加注释：

    -- 节点：
    -- 粒度：
    -- 来源：
    -- 用途：

------------------------------------------------------------------------

# 五、ADS生成规则

## 1. ADS定位

ADS用于服务分析展示。

不是复杂计算层。

------------------------------------------------------------------------

## 2. ADS生成原则

推荐：

    FACT
     ↓
    TMP_BASE（可选）
     ↓
    TMP_METRIC（可选）
     ↓
    ADS

    # ADS生成原则

生成ADS时：

不要默认生成指标结果字段。


例如：

不要生成：

REARER_CNT
ALERT_CNT
WARNING_RATE


除非model_design明确要求。


优先输出：

业务明细字段：

REARER_ID
POP_ID
ALERT_TYPE_CD
STATUS_CD
ALERT_DT


让BI层根据筛选条件进行聚合。

------------------------------------------------------------------------

## 3. ADS禁止

禁止：

-   大量WITH嵌套
-   重复扫描FACT
-   一个SQL中完成所有指标
-   多个明细事实表直接JOIN

------------------------------------------------------------------------

## 4. ADS粒度

生成前必须声明：

    ADS名称：
    最细粒度：
    维度：
    指标：

ADS不能改变既定粒度。

------------------------------------------------------------------------

# 六、字段映射规则

根据mapping.yaml生成字段。

支持：

## direct

直接映射：

    source.field AS target_field

------------------------------------------------------------------------

## transform

转换逻辑：

例如：

    CASE WHEN STATUS_CD='1'
    THEN '持续中'
    END AS STATUS_NM

------------------------------------------------------------------------

## constant

固定值：

例如：

    '生产异常' AS EVENT_TYPE_NM

------------------------------------------------------------------------

## derived

计算字段：

例如：

    DATEDIFF(CLOSE_DT,OPEN_DT)

------------------------------------------------------------------------

## aggregate

聚合字段：

必须明确：

-   GROUP BY字段
-   聚合函数

------------------------------------------------------------------------

# 七、SQL格式要求

必须遵守：

## SELECT

使用字段前逗号：

``` sql
SELECT
      A.ID
    , A.NAME
    , A.DT
```

------------------------------------------------------------------------

## 禁止

    SELECT *

------------------------------------------------------------------------

## JOIN

推荐：

``` sql
LEFT JOIN TABLE B ON A.ID=B.ID
```

不要无意义换行。

------------------------------------------------------------------------

## WHERE

保持简洁：

``` sql
WHERE A.STATUS_CD='C'
AND A.DATEKEY=DATE_SUB(CURRENT_DATE(),1)
```

------------------------------------------------------------------------

# 八、DDL要求

每个建表SQL必须包含：

-   字段
-   COMMENT
-   表COMMENT
-   存储格式

示例：

    CREATE TABLE TABLE_NAME
    (
     FIELD STRING COMMENT '说明'
    )
    COMMENT '业务说明'
    ;

------------------------------------------------------------------------

# 九、INSERT要求

统一：

    INSERT OVERWRITE TABLE

必须明确：

-   字段顺序
-   来源字段
-   转换逻辑

------------------------------------------------------------------------

# 十、验数SQL生成

每个模型生成对应验数：

## 数据量

    COUNT(*)

## 主键重复

    GROUP BY KEY
    HAVING COUNT(*)>1

## 金额/数量校验

源目标SUM比较。

## 关联完整性

LEFT JOIN检查。

------------------------------------------------------------------------

# 十一、最终输出格式

生成文件：

    output/sql/

    ├── fact_xxx.sql
    ├── tmp_xxx.sql
    ├── ads_xxx.sql
    └── validate_xxx.sql

------------------------------------------------------------------------

# 十二、生成前最终检查

生成SQL前必须确认：

1.  是否存在FACT？
2.  FACT粒度是否明确？
3.  是否使用已有模型？
4.  是否需要TMP拆分？
5.  ADS是否过重？
6.  JOIN是否存在数据放大？
7.  字段命名是否符合规范？
8.  是否包含验数SQL？

如果发现模型设计问题，不直接生成错误SQL，应先提出问题。
